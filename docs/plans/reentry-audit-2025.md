## SECTION 3 — CODE QUALITY ISSUES

### 3.1 Error handling gaps

**Unhandled: `readFileAsArrayBuffer` return type mismatch (minor)**

`main.js:323` returns:
```javascript
return buffer.buffer.slice(buffer.byteOffset, buffer.byteOffset + buffer.byteLength)
```
This is an `ArrayBuffer`. Electron's contextBridge serializes `Buffer` as `Uint8Array` in the renderer, but an `ArrayBuffer` may pass through differently. `pdfviewer.html:439` passes it as `{ data: arrayBuffer }` to `pdfjsLib.getDocument()`. PDF.js accepts both `ArrayBuffer` and `Uint8Array` — no crash expected, but the behavior is undocumented for this exact path. Low risk; worth verifying on Windows during testing.

**`renderPending` guard in pdfviewer.html (minor UX issue)**

`pdfviewer.html:288–290`: If the user clicks Prev/Next while a render is in progress, the new navigation request is silently dropped (early `return`). On a slow PDF this could cause the user to click multiple times without visible response. Not a crash — just a UX friction point.

**`doGeneratePdf()` button re-enable in step4.js**

`step4.js:352-354`: `btn.disabled=false; genBtn.disabled=false; backBtn.disabled=false` runs unconditionally after the try/catch block. The catch block also re-enables `genBtn` and `backBtn` but not `btn`. This means on error, `btn` is re-enabled by the post-catch line. This is functionally correct but structured unexpectedly.

### 3.4 Session file cleanup on app quit

Session files in `~/.sol-quoter/session/current/` are **not cleaned up on app quit**. This is by design — they persist so resumed sessions can still access source documents. Cleanup happens at the start of the next `/parse` call (`server.py:167`: `clear_session_dir()`).

The `atexit` handler (`server.py:41–49`) only sweeps `_active_tmp_files` (the old temp file set), not the session directory. Session files can therefore accumulate across app restarts if the user never re-parses. This is acceptable per the Phase 2 design decision (E5 in phase2-session-persistence-plan.md: "bounded to ~3 files at a time; manual deletion of `~/.sol-quoter/` is safe and documented").

On Windows, the `taskkill` call in `main.js:89` kills the Python process without cleanup — Flask's atexit handlers may not run on Windows `taskkill`. Session files still exist afterward (they are not in `_active_tmp_files`), so no files are lost.
